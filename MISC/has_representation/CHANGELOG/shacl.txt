CHANGELOG -- representation.shacl.ttl
=====================================

Applied
-------
1. Corrected the QUDT schema namespace.

2. Changed the unit contract from exactly one to zero-or-one. REP-UNIT-003
   now applies maxCount 1 and IRI validation without minCount.

3. Reframed REP-UNIT-001 as a whitelist rule. Failure means the pair is
   unsupported by this application profile; no claim of physical
   incompatibility is made.

4. Extended quantity-kind resolution through qb:attribute as well as direct,
   qb:dimension and qb:measure paths.

5. Added REP-UNIT-004. Every representation component must have exactly one
   IRI-valued resource typed as qudt:QuantityKind, including when no unit is
   supplied.

6. Added REP-UNIT-005. Every unit-bearing subject must resolve to exactly one
   quantity kind. Referenced components are checked individually so one valid
   component cannot mask another component with missing metadata.

7. Retained per-representation warnings REP-UNIT-010 through REP-UNIT-016.
   They run only when a unit value is present.

Operational requirement
-----------------------
The shp:permitsUnit table is trusted validator configuration. It must be
visible to the SHACL-SPARQL query and must not be extensible by producer data.
